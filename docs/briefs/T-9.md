# T-9: which tabs show

- **Risk:** low.
- **Reads:** SPEC.md section 4, row T-9; criterion AC-19; docs/GAME-DESIGN.md sections 17 (the tab list) and 18
  (the first minute); src/core/state.ts, src/core/research.ts, src/core/data.ts.
- **May change:** src/core/reveal.ts, src/core/state.ts, src/core/step.ts, src/core/data.ts, test/reveal.test.ts.
- **Build:** a pure rule for which tabs the page shows. Once a tab has shown it never hides again, even after a
  bake, so a returning player never loses a screen.
- **How:**
  - `state.revealed` is a list of tab names, starting `["Jar", "Settings"]`. Add `state.peakFlour` (the most flour
    held at once this batch) and `state.murmursEver` (all murmurs ever made); step.ts keeps both up to date.
  - `updateReveal(state)` runs at the end of every step and adds each tab whose rule holds:
    Work when `peakFlour >= 25` (five feeds); Murmurs when `murmursEver >= 1`; Build when "Fermentation" is
    bought; Fridge when "Acid Wall" is bought; Chronicle when "Writing in Foam" is bought. The later tabs (Bake,
    Heritage, Trials, Strains, Bakery, Crumb Shots) come with their own tasks; list them in data.ts as not yet
    revealable.
  - `isShown(state, tab)` is written exactly `return state.revealed.includes(tab);` (once).
  - Required examples, each an assertion: a new game shows Jar and Settings only; four feeds do not show Work and
    a fifth does; Build shows the step after Fermentation is bought; a tab shown before stays shown after its
    research is removed from the state (as a bake will do).
- **Done means:** `npx vitest run -t "reveal: a tab appears only when its system unlocks"`, `npx tsc --noEmit`,
  the gates.
- **Breaks:**

```
test/reveal.test.ts.reveal: a tab appears only when its system unlocks fails when src/core/reveal.ts has `return state.revealed.includes(tab);` as `return true;`
```
