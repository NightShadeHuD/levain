# T-4: saving and loading

- **Risk:** medium (a bad save loses a player's progress).
- **Reads:** SPEC.md section 4, row T-4; criteria AC-10, AC-11, AC-12, AC-74; docs/GAME-DESIGN.md section 11;
  src/core/state.ts.
- **May change:** src/core/save.ts, src/core/data.ts, test/save.test.ts, test/fixtures/save-v1.json.
- **Build:** turning a state into text and back, checking imported text, and the migration list. Only pure
  functions: writing to localStorage is the page's job (T-10 and T-35).
- **How:**
  - `serialise(state)` returns JSON text. `deserialise(text)` returns `{ ok: true, state }` or
    `{ ok: false, problem }`, where `problem` is a plain sentence ("not JSON", "no version field", "made by a
    newer version of Levain (3); this is version 1", "field resources.flour is not a number").
  - `exportText(state)` is the save in base64 (`btoa` of the JSON, UTF-8 safe); `importText(text)` accepts that
    or plain JSON, with whitespace around it.
  - Every field of the current state is checked: present, the right type, numbers finite and not negative.
    Any failure returns `ok: false`. The caller's state is never touched by a failed import.
  - `MIGRATIONS` is a list of functions; entry i turns a version-i save into version i+1. Loading runs every
    one from the save's version up to `SAVE_VERSION`. There are none yet (version 1); the test must still load
    the fixture `test/fixtures/save-v1.json` (write it from `newGame(1)` after 30 s and 7 feeds).
  - A save whose version is above `SAVE_VERSION` is refused with the "newer version" problem (AC-74).
- **Done means:** `npx vitest run -t "save: round trip gives an identical state"`,
  `npx vitest run -t "save: a bad import changes nothing and names the problem"`,
  `npx vitest run -t "save: every old version migrates"`, `npx vitest run -t "save: a newer version is refused"`,
  `npx tsc --noEmit`, `bash tests/gates.sh`. The bad-import test covers: empty text, text that is not JSON, a
  missing field, a field of the wrong type, a negative number, the string "NaN" as a number, and `1e999` (JSON reads it as Infinity).
- **Breaks:**

```
save: a newer version is refused fails when src/core/save.ts has `> SAVE_VERSION` as `> SAVE_VERSION + 1`
save: a bad import changes nothing and names the problem fails when src/core/save.ts has `Number.isFinite(` as `!Number.isNaN(`
```
